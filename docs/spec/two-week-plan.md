# Two-Week Alpha Plan

## Delivery Principle

Contract-first parallel development with one integration owner. Every day preserves a runnable vertical slice; no module may report success through a placeholder path.

## Days 1-2: Walking Skeleton

- Repository, scoped `AGENTS.md`, Schema registry, state model.
- Fake and pi runtime contracts.
- Package import, basic problem planning, task graph validation.
- One Python experiment through Docker, evidence record, minimal PDF.

## Days 3-5: General Task Execution

- Unified `TaskExecutor` and all eight plugin descriptors.
- General generated-code protocol plus tested baseline components.
- Evaluation-contract freeze, result validation, bounded repair.
- SQLite checkpoints, staging/commit semantics, resume and cancellation.

## Days 6-8: Input, Evidence, Report

- PDF/DOCX/table/numeric/image package inventory and bounded extraction.
- DuckDB profiling for large tables.
- Evidence Graph, citation registry, report sections, XeLaTeX export.
- Independent reproducibility command.

## Days 9-10: Research And UI

- Audited OpenCLI gateway, prompt-injection isolation, reference firewall.
- Fastify REST/SSE service and local React operational UI.
- Human checkpoints, overrides, stale-dependency propagation.

## Days 11-12: Reliability

- Security policy tests, failure injection, budgets, deadlines.
- Eight synthetic plugin scenarios and full package verification.
- First historical-problem development runs and targeted fixes.

## Days 13-14: Evidence

- Three historical blind runs.
- One-shot baseline and selected ablations.
- Architecture, ADRs, failure cases, benchmark report, demo script.

## Scope Control

The architecture is general. A method without a dedicated validator remains `experimental`. Any incomplete path must fail explicitly; it cannot return a successful placeholder artifact.
