# v0.1-alpha Product Specification

## Objective

Given a mathematical-modeling competition package, produce one complete project package containing the requested submission artifacts plus reproducible code, experiments, figures, evidence, and environment metadata.

This alpha is a general architecture and best-effort implementation. Quality claims require frozen benchmark evidence.

## Fixed Outer Lifecycle

1. Import and audit the package.
2. Freeze competition and deliverable rules.
3. Extract requirements and data semantics.
4. Plan a typed task graph.
5. Review requirement coverage and validate the DAG.
6. Freeze evaluation contracts before observing candidate outcomes.
7. Execute and validate candidate experiments.
8. Select or retain Pareto candidates using programmatic evidence.
9. Build the Evidence Graph.
10. Generate and audit the report.
11. Export and verify one project package.

## Dynamic Inner Graph

Each task node declares a registered task type, requirement coverage, dependencies, input artifacts, output contract, evaluation contract, budget, and evidence level. Unknown methods run through `custom_experiment` and are marked experimental.

## Non-Negotiable Policies

- Original inputs are immutable.
- Metrics are frozen before candidate results are observed.
- Precise report claims resolve to committed evidence.
- Same-problem references are unavailable during blind solve.
- External data is forbidden unless the problem explicitly requires it and a user approves the request.
- Workers cannot commit state or artifacts directly.
- Ambiguous semantics and permission changes block for user input.
- A deadline-aware run preserves a last-submittable checkpoint.

## Alpha Acceptance

- Deterministic synthetic coverage for all eight registered task families.
- Three complete historical-problem blind runs spanning at least six task families and one custom experiment.
- Clean-container experiment reproduction and report rebuild.
- Zero silent data truncation, unsupported-success claims, unbound numeric claims, or unauthorized external data.
- Comparison against a one-shot prompt baseline with completion, hard-error, time, token, cost, and human-review metrics.
